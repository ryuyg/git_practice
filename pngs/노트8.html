먼저 알아둘 말 — ISA와 설계 경향

ISA — 소프트웨어와 CPU 사이의 실행 약속(명령어·레지스터·주소 규칙 등).
마이크로아키텍처 — 그 약속을 칩 안에서 어떻게 구현했는지(파이프라인·캐시·실행 유닛 수 등).
CISC — 복잡한 일을 한 명령에 담는 설계 경향.
RISC — 단순한 명령을 빠르게 많이 처리하는 설계 경향.
ABI — 함수 인자 전달·바이너리 연결 등 실행 파일·라이브러리 연결의 세부 규칙. ISA와 별개로 호환에 영향을 준다.

한 줄로: 앱은 ISA를 보고 만들고, 같은 ISA라도 칩 내부(마이크로아키텍처)는 세대마다 달라도 됩니다.

01

ISA란 무엇인가

소프트웨어와 CPU가 함께 지키는 약속

ISA(Instruction Set Architecture, 명령어 집합 구조)는 명령어의 종류·의미, 소프트웨어에 보이는 레지스터, 주소 지정 규칙 등 실행에 필요한 약속을 정의합니다. 컴파일러는 이 약속을 보고 소스 코드를 기계어로 번역합니다. 같은 코드를 x86-64와 Arm 대상으로 각각 컴파일하면, 서로 다른 기계어가 만들어질 수 있습니다.

먼저 알아둘 말 — 헷갈리기 쉬운 말

바이너리(기계어 프로그램) — CPU가 실행하는 비트 패턴으로 된 명령 열.
호환 — 같은 실행 파일이 그대로 돌아가는지. ISA·OS·ABI·라이브러리가 모두 영향을 준다.
마이크로옵(마이크로연산) — 외부에 보이는 복잡한 명령을 CPU 내부에서 더 작은 동작으로 나누어 실행하는 단위.
에뮬레이션 — 다른 ISA용 프로그램을 변환·해석 계층으로 실행하는 방법. 네이티브 실행과 구분된다.

한 줄로: "CPU가 같다"는 것만으로 실행 파일이 항상 호환되지는 않습니다.

02

ISA와 마이크로아키텍처

약속은 그대로, 구현은 세대마다 달라도 된다

마이크로아키텍처는 ISA라는 약속을 실제 하드웨어로 구현한 방식입니다. 같은 ISA를 구현하더라도 파이프라인 깊이, 캐시 크기, 실행 장치 수는 세대마다 달라질 수 있습니다. ISA가 내부 설계에 영향을 주긴 하지만, 하나의 내부 구조만을 반드시 정하는 것은 아닙니다.

즉 같은 ISA를 지키면 같은 기계어 프로그램이 돌아갈 수 있고, 칩 내부 구현은 세대마다 얼마든지 달라질 수 있습니다. 앱 개발자는 ISA만 보고 프로그램을 만들고, 칩 회사는 그 약속을 지키는 한 내부를 자유롭게 개선합니다.

03

CISC와 RISC — 두 가지 설계 경향

복잡한 명령 하나 vs 단순한 명령 여러 개

ISA를 설계할 때 크게 두 가지 경향이 있었습니다. CISC(Complex Instruction Set Computer)는 복잡한 일을 한 명령에 담는 쪽이고, RISC(Reduced Instruction Set Computer)는 단순한 명령을 빠르게 많이 처리하는 쪽입니다.

강의는 메모리가 귀했던 시절, 복잡한 명령으로 프로그램을 짧게 표현하는 CISC의 장점을 설명합니다. 동시에 복잡한 명령을 아무리 많이 제공해도 실제 프로그램에서는 그중 일부만 자주 쓰인다는 문제의식도 소개합니다.

"20%가 80% 사용" — 측정값이 아니라 비유

강의의 "명령어의 20%가 실제 사용의 80%를 차지한다"는 표현은 빈도가 한쪽으로 쏠린다는 것을 보여주는 사례일 뿐입니다. 모든 ISA·모든 프로그램에 그대로 적용되는 정확한 측정값으로 외우지 않도록 주의하세요.

05

Load/Store 방식

메모리 접근과 계산을 분리하면, 각 명령은 단순해진다

RISC 경향이 왜 여러 명령어를 필요로 하는지는 Load/Store 방식의 예를 보면 이해가 됩니다. 메모리 값 두 개를 각각 레지스터로 LOAD하고, 레지스터끼리 ADD한 뒤, 결과를 STORE로 메모리에 저장합니다. 명령어 개수는 여러 개일 수 있지만, 각 명령이 맡는 역할은 단순해집니다.

이렇게 메모리 접근(LOAD/STORE)과 계산(ADD 등)을 분리하면, 계산 명령어는 "메모리에 접근할 수도, 안 할 수도 있는" 복잡한 경우를 고려하지 않고 항상 레지스터만 다루면 됩니다. 이 규칙성이 파이프라인 설계를 단순하게 만드는 데 도움이 됩니다.

06

마이크로옵 — 내부 변환

겉은 CISC, 속은 RISC 조각일 수 있다

현대 x86 CPU는 겉으로는 복잡한 명령 하나로 보이는 것을, CPU 내부에서 더 작은 동작인 마이크로옵(micro-op)으로 나누어 처리하기도 합니다. 예를 들어 메모리에 직접 값을 더하는 복잡한 명령 하나가, 내부적으로는 앞서 본 Load/Store 방식과 비슷한 여러 조각으로 쪼개질 수 있습니다.

이것이 "x86이 RISC가 됐다"는 뜻은 아니다

내부적으로 마이크로옵으로 나누어 처리한다고 해서, x86의 외부 ISA 자체가 RISC로 바뀌는 것은 아닙니다. 소프트웨어에게 보이는 명령어 집합(ISA)은 여전히 x86이고, 마이크로옵으로의 분해는 어디까지나 내부 마이크로아키텍처의 구현 선택입니다. 반대로 RISC도 모든 명령이 반드시 한 클럭에 끝나는 것은 아니며, 고정 길이 명령만 존재하는 것도 아닙니다.

07

호환성은 ISA만으로 정해지지 않는다

CPU가 같다고 실행 파일이 항상 돌아가는 것은 아니다

다른 컴퓨터에서 실행 파일이 돌아가지 않는 원인은 ISA뿐만이 아닙니다. 운영체제, 실행 파일 형식, ABI, 라이브러리의 차이일 수도 있습니다. 실행 파일이 그대로 돌아가려면 아래 네 가지가 모두 맞아야 합니다.

그림 6. 실행 파일이 그대로 돌아가려면 ISA뿐 아니라 운영체제·ABI·라이브러리까지 맞아야 한다.

ABI(Application Binary Interface)는 함수 인자를 어떻게 전달하는지, 바이너리를 어떻게 연결하는지 등의 세부 규칙입니다. CPU의 ISA가 같다고 해서 모든 실행 파일이 그대로 호환되는 것은 아닙니다 — 에뮬레이션이나 변환 계층이 서로 다른 ISA·환경 사이의 호환을 돕는 경우도 있습니다.

08

실제 ISA 예시

x86, Arm, RISC-V는 서로 다른 약속이다

x86/x86-64, Arm, RISC-V 등은 서로 다른 ISA입니다. 바이너리는 서로 호환되지 않는 것이 기본입니다. 현대 CPU는 외부에 보이는 ISA와 내부에서 실제로 실행되는 마이크로옵이 다를 수 있으며, 컴파일러는 항상 대상 ISA에 맞춰 기계어를 생성합니다.

한 문장 요약

ISA는 소프트웨어와 CPU가 함께 지키는 실행 약속이고, 마이크로아키텍처는 그 약속을 칩 안에서 구현한 방법입니다. CISC와 RISC는 이 약속을 설계할 때의 두 가지 경향일 뿐이며, 실행 파일이 실제로 돌아가려면 ISA뿐 아니라 운영체제·ABI·라이브러리까지 함께 맞아야 합니다.
